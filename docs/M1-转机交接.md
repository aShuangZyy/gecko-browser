# M1 转机交接（从零到出包）

> 目标：把「在这台 Windows 上做的事」搬到租来的 M1 上继续做。
> 需要搬的是**两样东西**：代码仓库（GitHub 上已经有了）+ 项目简报 `CONTEXT.md`。
> 工作目录 `C:\code\blackapple` 里只有文档、脚本和 overlay，源码真身在 fork 里。

---

## 0. 先回答那个问题：需要传的是什么

「你」不是一个文件，没法复制。分清楚三件事：

| 东西 | 在哪 | 怎么过去 |
|---|---|---|
| 代码（Gecko 引擎 + 外壳） | `https://github.com/aShuangZyy/gecko-browser` | `git clone`，不用传 |
| 文档、脚本、overlay 源文件 | 本机 `C:\code\blackapple` | 推到仓库 `docs/` 或打包，见 §3 |
| 会话记忆（做到哪一步、踩过哪些坑） | 本机 DSH 会话 | 已沉淀成 `CONTEXT.md`，随仓库走 |

所以 M1 上只要：装 DSH → clone 仓库 → 读 `CONTEXT.md` → 跑构建。

## 1. 在 M1 上装 DSH

```bash
# 需要 Node 22+（这边是 v24.20.0）
node -v
npm -v

npm install -g @deepseek-ai/dsh
dsh --version          # 这边是 0.2.0-rc.2
```

然后照常配置模型/API 凭据（和这边同一套），在项目目录里 `dsh` 启动，让它读 `CONTEXT.md` 接手。

DSH 是 CLI 工具，**不依赖 Windows**，装在哪台机器上就在哪台机器上跑命令。

---

## 2. 先把仓库拉下来

```bash
mkdir -p ~/code && cd ~/code
git clone https://github.com/aShuangZyy/gecko-browser.git
cd gecko-browser
```

公开仓库克隆**不需要 token**。要 push 才需要，见 §4。

## 3. 文档怎么过去（三选一）

**A. 走 GitHub（推荐）**
把本机 `C:\code\blackapple\docs\` 和 `C:\code\blackapple\gecko-browser\` 推到一个私有仓库，M1 上 clone。适合长期迭代。

**B. 打包传**
```powershell
# Windows 这边
Compress-Archive -Path 'C:\code\blackapple\docs','C:\code\blackapple\gecko-browser' `
                 -DestinationPath "$env:USERPROFILE\Desktop\blackapple.zip" -Force
```
然后在 M1 上通过 AirDrop / 网盘 / `scp` 拿过去解压。

**C. 只要最少的东西**
其实 M1 上构建**只需要仓库本身**：`engine/`、`patches/`、`tools/`、`browser/` 全在里面，`tools/development/*.sh` 就是完整的构建脚本。文档只是给人看的。

```bash
scp -r you@this-pc:/path/to/blackapple/docs ~/code/gecko-browser/docs
```

## 4. Token 的事（重要）

之前用的那个 GitHub token 已经出现在聊天记录里，**去 GitHub 撤销重建一个**：
Settings → Developer settings → Personal access tokens。

- 只要 clone：不用 token
- 要 push / 触发 Actions：新 token 用环境变量传，别写进文件

```bash
export GITHUB_TOKEN='新token'
```

在 M1 上构建**不需要 token 也不需要 Actions**——本地直接编，比等云端快得多。

## 5. 在 M1 上首次构建

```bash
# 5.1 工具链
brew install python@3.12 lld cbindgen llvm sccache
rustup target add aarch64-apple-ios
xcode-select --install          # 若没装命令行工具

# 5.2 拉 Gecko 源码（约 2GB，几分钟）
./tools/development/update-gecko.sh

# 5.3 打补丁
./tools/development/apply-patches.sh

# 5.4 编 idevice（JIT 配对用，Rust）
./tools/development/build-idevice.sh

# 5.5 编 Gecko（M1 冷构建 25–40 分钟；关 LTO 更快）
./tools/development/build-gecko.sh --use-sccache --auto-clobber

# 5.6 出未签名 app + TrollStore tipa
./tools/release/build-app.sh --no-signing
./tools/release/create-ipa.sh --trollstore
```

产物在 `dist/Reynard-TrollStore.tipa`。

> 冷构建那次（GitHub 4 核）花了 5h24m；M1 是 8 核，且 sccache 第二次起会命中。
> 只想改 UI 的话，`build-app.sh` + `create-ipa.sh` 两分钟就够，Gecko 不用重编。

## 8. 排错速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `cannot find type 'GeckoSession'` | 少了 `import GeckoView` | GeckoView 是独立 framework target，必须 import |
| 白屏 / 黑屏 | 生命周期顺序错 | `GeckoSession(settings:)` → `open(windowId:)` → `geckoView.session = session` → `setActive(true)` → `load()` |
| 启动即崩 | JIT 没起来 | TrollStore 版需要 `ldid -S` 私有 entitlements + `ts_ptrace_jit` |
| `fatalError: attempt to assign GeckoSession to multiple GeckoView` | 一个 session 赋给了两个 view | 一个 session 只配一个 GeckoView |
| 链接点了没反应 | 缺 `interactionDelegate` | GeckoView 需要单独设置 |
| x.com 报 `address wasn't understood` | 外部协议没人拦 | `onLoadRequest` 返回 `.deny` 并自己处理 |
| 构建卡在 `EXITBS` / 队列很久 | runner 稀缺 | 本地编，不要等云端 |
